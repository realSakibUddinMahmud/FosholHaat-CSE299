Required rules:

1. use the approved Seller desktop shell as the exact canonical web base once approved
2. preserve `#1A5632`, `#F8FAF9`, `#F4F6F5`, white-card surfaces, and Seller-family operational hierarchy
3. preserve Inter typography and restrained B2B trust tone
4. preserve supply-first desktop layout logic
5. keep orders secondary and payouts restrained
6. request one canonical screen only unless shell exploration is explicitly intended
7. keep Seller desktop supply-first, orders-second, payouts-third
8. use dense modules only when they speed operational action
9. reject visually unfinished lower-page areas and tertiary rails that are too weak to read
10. reject clipped left-rail content, cramped outer padding, or low-radius admin-box geometry
11. require a stable Seller header, restrained Seller footer, and a supply-oriented home block

Prompt must explicitly include:

- base shell id
- exact token rules
- exact desktop anatomy
- required module priority
- anti-drift constraints
- exact screen purpose
- whether the screen should feel like an operations desk, fulfillment surface, or supply record workspace

Do not allow:

- generic admin-dashboard chrome
- analytics-wall drift
- payout-first layout logic
- buyer-home visual patterns
- logistics-control-tower styling
- duplicate actions or redundant control clusters
- cut-off content or cropped navigation labels

Seller web-specific guidance:

- mobile defines flow logic
- web shell defines layout logic
- Seller desktop should improve supply scanning, stock visibility, and order handling
- payout visibility supports the workspace but must not define the shell

## Seller Web Prompt Heuristics

Use these phrasing patterns when generating Seller desktop prompts:

- `supply-first operations desk`
- `inventory visibility before payout visibility`
- `order handling as secondary but live operational context`
- `rounded desktop modules with dense but calm action readiness`
- `one meaningful support rail only if it improves fulfillment continuity`

Reject prompt language that implies:

- payout-first desktop logic
- finance-panel composition
- analytics-first dashboarding
- marketplace browsing behavior

## Candidate Review Heuristics

Treat a Seller desktop candidate as suspect if it shows:

- shell logic dominated by payout or finance modules
- lower page areas that feel visually unfinished
- tertiary rails with weak task value
- clipped navigation labels or cramped filters
- generic KPI blocks replacing inventory or fulfillment modules
- boxy low-radius admin geometry
