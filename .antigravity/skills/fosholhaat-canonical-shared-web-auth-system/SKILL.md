Required rules:

1. use the approved shared web-auth shell as the exact canonical web base once approved
2. preserve `#1A5632`, `#F8FAF9`, `#F4F6F5`, white premium surfaces, and shared-entry family tone
3. preserve Inter typography and calm branded trust hierarchy
4. preserve role-neutral auth layout logic
5. request one canonical screen only unless shell exploration is explicitly intended
6. keep shared desktop auth role-neutral at shell level
7. keep the page brand-first and trust-first, not marketing-first
8. ensure there is only one clear primary login entry point in the shell unless a second one has a distinct purpose
9. require elegant rounded auth containment and reject flat template auth geometry
10. require a stable shared header, restrained shared footer, and a trust-first entry home block

Prompt must explicitly include:

- base shell id
- exact token rules
- exact auth-card and shell anatomy
- bilingual-treatment requirement where relevant
- anti-drift constraints
- exact screen purpose
- whether the screen should feel like welcome-entry, login-entry, or role-branching entry

Do not allow:

- generic SaaS auth templates
- hero-photo landing pages
- fintech auth styling
- role-specific signup forms in shared auth
- Hub self-registration
- duplicate login buttons or duplicated auth actions
- footer clutter that weakens first-touch polish
- boxy enterprise auth-card geometry

Shared web-auth guidance:

- mobile defines flow logic
- web shell defines layout logic
- desktop shared auth should improve brand trust, bilingual clarity, and access decisions
- role-specific account-creation forms belong outside the shared shell

## Shared Web-Auth Prompt Heuristics

Use these phrasing patterns when generating shared desktop auth prompts:

- `brand-first trust entry`
- `role-neutral access surface`
- `single clear primary login path`
- `elegant rounded auth containment`
- `bilingual clarity without clutter`

Reject prompt language that implies:

- generic SaaS auth template
- landing-page hero behavior
- multi-CTA login clutter
- role-specific signup form entry

## Candidate Review Heuristics

Treat a shared desktop auth candidate as suspect if it shows:

- duplicated login actions with the same purpose
- footer clutter diluting first-touch polish
- flat or boxy enterprise auth geometry
- hero-photo marketing behavior
- weak language treatment
- shell-level role drift into Buyer, Seller, or Hub-specific signup behavior
